# Changelog

## Unreleased

- Writer sandboxes get a private temp dir (`TMPDIR`/`TMP`/`TEMP` under the sandbox root), drop `XDG_SESSION_TYPE` and `COLORTERM`, and drop the host Claude Code session's plugin directories from `PATH`. With the host temp dir, the checkout and HOME sat under the OS temp dir, which Showtail-style tools treat as scratch; Electron (VS Code extension tests under `xvfb-run`) chose Wayland from the session type and exited, and TUI tests asserted a 256-color palette under the host's truecolor terminal. This changes the writer contract. Add `scripts/check-runnability.ts`, which runs each case's main check command at head in a writer sandbox (same preparation and fixtures) and records pass/fail/env-error/no-command per case.
- Add `prbench fact-review`: an expert model panel (default 3 Opus 5.5 + 3 Sol 6.1 at xhigh) reviews each fact sheet against the raw evidence in read-only agentic sessions. Family consensus settles items, an Opus synthesis plus a round-2 panel vote settles rewrites and clustered additions, and everything else goes to `human-review.md`. Includes planted-error canary calibration with a PASS/FAIL bar, `--resume` keyed by call inputs, `--aggregate-only` for sealed cases, and `--apply`, which rewrites the case sheet with an `expert-panel` provenance. Judge providers gain a read-only agentic mode (`ask(..., { workDir })`). See `docs/fact-review.md`.
- Run comparisons end to end on Codex or Claude (`compare --provider codex|claude|both`) as one parallel job graph (`--parallel <n>`). `--models` chooses the writer models (optionally `model@effort`) and keeps the provider's judges.
- Add `compare --systems baseline,candidate` to skip native writers and judge only candidate vs baseline. A subset of systems is part of the experiment identity.
- Add `prbench score <runs…>`: absolute per-draft scores (coverage, rubric, factual errors, unsupported claims, traps) on a documented 0–100 composite, with case-clustered bootstrap intervals, paired and per-case deltas, leave-one-case-out ranges, an accuracy view, and writer and judge reliability tables. It works on existing runs.
- Price Codex writers across every thread, subagents included, at each model's own rate (`meta.usageByModel`, `src/report/prices.json`). Claude records per-model usage from `modelUsage`. Older runs are re-priced from their saved traces.
- Retry writers that time out, leave no draft, or have their draft rejected by the scope audit (up to 3 attempts, reported per arm). Writer output is cached only after it passes the scope audit.
- Retry timed-out and transient judge calls with backoff. Judge reference fields are constrained by a per-prompt schema, so a judge cannot cite IDs that a side lacks; an invalid judgment still gets one correction request before it counts as a failure.
- Make concurrent controllers safe. Preflight mirrors are cloned beside their final path and renamed into place, and ref-lock fetch conflicts are retried. Parallel Codex runs share the dedicated login through a symlink, and an exclusive-copy run joins the shared link while another controller holds it, so it never writes a stale token back.
- Set timeouts through the environment: `PRBENCH_WRITER_TIMEOUT_MS` (frozen in the experiment) and `PRBENCH_JUDGE_TIMEOUT_MS` / `--judge-timeout-ms` (may be raised on resume).
- Add `crossjudge` to judge the candidate drafts of one finished run against the baseline drafts of another, using `compare`'s consensus rule.
- Add `scripts/paired-delta.ts` to compare two runs pair by pair against their own baselines: consensus outcome counts and composite Δ-of-Δ with a case bootstrap interval.
- Add `docs/reproduce-graph-vs-base.md`, which explains how to repeat the Tracetoon graph-vs-base comparison.
- Adoption gate and admission accept a candidate either by the three-role rule or by the lean reviewed path: a current v2 review whose recorded passes meet the run's review plan (pass count from distinct reviewer agent ids, the planned lenses, the planned reviewer model and effort, tool-run verified passes when the plan asks for them). `meta.workflow` now records `reviewPlan` and `reviewPasses` from Tracetoon's `review-plan.json` and `review.json`; workflow gaps name each failed requirement.
- Performance gate: when validation did not complete for either writer in every pair (the sandbox could not run it), the report sets `validationUnavailable`, states it as a limitation (also in the comparison summary) and lets timing and tokens decide; matched, unmatched, one-sided and mixed results keep their previous effect.
- Add `--aggregate-only` to `prbench score`, `scripts/paired-delta.ts` and `scripts/qualify-cases.ts` for sealed runs: only overall tables (composite and interval, W/T/L, errors, cost) are printed, with no per-case rows or deltas, no leave-one-case-out ranges and no case names; with `--json` they print aggregates only.
- Quality gate accuracy compares with the baseline instead of zero tolerance. Accuracy flags are collected on candidate and baseline drafts (findings carry `arm`; old findings and adjudication entries without one are candidate flags, and candidate finding ids are unchanged). Every flag on both arms must be adjudicated, else the gate is inconclusive and lists each open flag with its arm. The gate fails when the candidate's confirmed errors per scored draft exceed the baseline's over the same candidate-vs-baseline pairs; `qualityGate.accuracy` and `summary.md` report both rates and counts. Changing `src/gates.ts` changes the gate policy hash.
- Performance gate is cost-based (`prbench.performance/v3`): it passes when the candidate/baseline geometric mean of paired per-draft priced cost (same model, case and replicate; log ratios averaged within each case, then across cases) is at most 1.000, using `prbench score` pricing (`draftCost`: reported totals where available, every model at its own price, cached input at its own rate, Codex across all threads). The case-clustered 95% interval is reported, not required. Any paired draft without a priced cost (unknown model price, missing tokens, Codex main-thread-only usage) makes the gate inconclusive and is listed in `unpricedDrafts` and `summary.md`, which states the rule. Writer wall time and token counts stay in the report as information, not criteria. The validation-comparability rules are unchanged. Changing `src/performance.ts` changes the gate policy hash.
- Fixes: Windows-recorded cases replay correctly on POSIX hosts. Codex command directories are recovered from rollout execution records. The fake `gh` handles `--help` and `--fill`. Shell and session bookkeeping is kept out of writers and out of environment identities. Isolation probes run at the configured effort and accept proofs saved for effort arms.

## 0.2.0

- Capture fresh writer command evidence for Claude and Codex in both native and tool flows, retaining results and explicit provenance limits before sandbox cleanup.
- Supply original work-session evidence and each writer's fresh validation evidence separately to blind judges.
- Introduce rubric v3 claim assessments: supported, contradicted, unsupported scope overclaim, and unverifiable due to missing evidence. Evidence-dependent preferences are reported as inconclusive.
- Preserve substantive validation statements during attribution normalization.
- Bind judging caches and report rebuilds to evidence, and keep incompatible historical results separate.
- Add `audit-evidence` for immutable historical draft copies and explicit, hash-checked recovery mappings. Missing historical execution records remain unavailable; old unsupported counts are not fabrication rates.
- Add `prbench --version` and a Bun-installable source release including replay helpers.

Historical rubric v2 reports are preserved. Use a new output directory for v3 judging. Human and cross-family judge calibration remain necessary; synthetic tests verify evidence handling and do not establish real judges' semantic accuracy.
